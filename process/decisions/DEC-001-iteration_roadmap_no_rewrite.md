# DEC-001：迭代一总体技术路线遵循“先稳平台基线，再做迭代二受控演进”

- 状态：确认
- 阶段：P1
- 日期：2026/4/17

## 背景

项目0在 P1 阶段需要完成迭代一功能清单、技术选型、系统架构、工程环境和 WBS/Sprint 规划，这些内容会直接驱动后续系统架构设计、ROS2 节点规划、接口定义、硬件方案和工程环境搭建。

项目0的版本路线中，V0.1 对应 P0-P1，表示项目定义收束、技术选型、系统架构设计与工程准备完成，项目进入可执行开发状态；V1.0 对应 P2-P6，表示迭代一完成并形成真实可运行、可复现、可扩展、可调试、可演示的具身智能小车基础平台。

同时，项目0在迭代二阶段原则上继承迭代一已验收的平台基线与工程骨架，重点变化通常发生在语义导航、开放集感知、任务策略、上层算法和研究增强模块；如需超出局部增强的调整，必须通过 CR / DEC、影响范围评估和回滚边界进行受控管理。

## 决策

项目0迭代一总体技术路线遵循：

> 先建立可运行、可复现、可调试、可演示的基础平台；迭代二原则上继承迭代一已验收的平台基线和工程骨架，避免无理由推翻重来；但对于语义导航、开放集感知、任务策略、上层算法和研究增强模块，可在明确 CR / DEC 支撑、影响范围评估和回滚边界的前提下受控演进。

具体约定：

1. 迭代一所有关键技术选型必须优先服务于最小闭环成立。
2. 迭代二原则上继承既有系统总架构、软件架构和接口骨架；如需对语义导航、开放集感知、任务策略、上层算法或研究增强模块做替代、重构、并行实验或新增路线，必须有明确 CR / DEC 支撑。
3. 不采用会无理由削弱已验收平台基线、安全边界、通信主链路与工程闭环的迭代一方案。
4. 若某项高级能力当前会显著增加复杂度，则优先推迟到迭代二，并在后续阶段结合影响范围评估决定是否进入 Execute。
5. 开放集方向、复杂语义理解等研究增强内容不视为当前已完成能力，也不写成当前阶段必须实现项。

## 理由

1. 迭代一目标是让执行层、感知层、空间认知层、行动规划层、任务决策层以及安全、管理、记录三条辅助链路全部成立，核心是最小闭环可运行。
2. 迭代一到迭代二的技术升级路径总体上以继承既有平台基线为前提，但并不排除在明确 CR / DEC 支撑下对研究增强模块做替代、重构或并行实验。
3. 软件架构的稳定主链路、安全链路和系统管理骨架应保持连续；语义导航、任务策略、上层算法及相关研究增强则可在不削弱安全、人工接管、急停、系统模式仲裁、电源边界、通信主链路和已验收平台基线的前提下受控演进。
4. 该决策有利于后续形成类论文式总报告、实验验证成果、答辩 PPT、演示视频和关键问题回答材料，因为技术路线连续、演进逻辑清晰。

## 影响

- 影响阶段：P1-P10 全过程。
- 影响模块：所有主链路模块与安全、管理、记录三条辅助链路。
- 影响文档：系统架构、软件架构、功能清单与技术选型、版本路线、WBS/Sprint 规划。
- 影响后续表达：项目报告、答辩 PPT、项目复盘、导师沟通材料。

## 回退条件（可选）

如果某个迭代一选型在 P2-P6 中被证明无法支撑真实平台最小闭环，且多次局部修正仍无法解决，则允许回退到更简单、更稳定、更可控的方案，但回退必须不破坏项目0总架构主链路。
