# DEC-005：迭代一语义导航采用 YAML 语义位置表 + 规则匹配

- 状态：确认
- 阶段：P1
- 日期：2026/4/17

## 背景

项目0的 P5 阶段需要实现基础语义导航，其边界是“语义输入 → 理解 → 导航目标转换 → 结果反馈”，导航执行本身归属于能力4。

迭代一功能清单明确：语义位置管理采用 YAML 语义位置表文件，用于维护语义标签与坐标映射；语义输入解析采用 ROS2 服务/话题接口 + 字符串精确匹配。

迭代一到迭代二技术升级路径明确：YAML + 规则匹配是迭代一语义导航基线；迭代二及后续研究增强可在 CR / DEC 支撑下引入更强语义解析、语义地图或并行实验路线，YAML 方案可继续作为兼容输入、回退路径或对照方案。

## 决策

项目0迭代一语义导航采用：

> YAML 语义位置表 + 规则匹配。

具体约定：

1. 使用 YAML 文件维护语义标签与地图坐标/区域之间的映射关系。
2. 语义输入解析采用确定性的字符串精确匹配或规则匹配。
3. 解析结果转换为导航目标，再交由 Nav2 执行。
4. 迭代一不引入 LLM 或复杂自然语言理解作为主链路。
5. 迭代二及后续研究增强可在 CR / DEC 支撑下引入更强语义解析能力，并可将 YAML 表 + 规则匹配保留为兼容输入、回退路径或对照方案。
6. 开放集方向或复杂自然语言理解不视为当前已完成能力，也不构成当前阶段必须实现项。

## 理由

1. 迭代一语义导航的目标是先跑通“语义输入到导航目标”的确定性链路，而不是直接做复杂语义理解研究。
2. YAML 语义位置表简单、透明、可编辑、易调试，适合单人开发和真机验证。
3. YAML 表 + 规则匹配已经能够提供迭代一可验证基线；后续如需引入 LLM、语义地图或其他解析路线，可在明确 CR / DEC、影响评估和回滚边界后与该基线并行、替代或重构。
4. 该方案便于后续在报告和答辩中清楚解释语义导航链路：语义标签如何定义、如何转换为坐标、如何触发导航执行。
5. 开放集语义导航、复杂自然语言理解等属于后续研究增强方向，不表示当前已经实现，也不应写成当前阶段交付义务。

## 影响

- 影响阶段：P5、P6、P9。
- 影响模块：p0_map_manager、p0_semantic_nav、p0_task_manager、p0_navigation。
- 影响文件：maps 或 config/semantic 下的语义位置表。
- 影响接口：语义目标查询、语义导航 action/service、任务状态反馈。
- 影响验收：语义目标识别、无效目标反馈、语义目标导航成功率。

## 回退条件（可选）

如果规则匹配无法覆盖迭代一验收所需语义输入，应优先收敛语义输入格式，而不是提前引入 LLM；只有在迭代二阶段且基础链路稳定后，再评估增强解析能力。
