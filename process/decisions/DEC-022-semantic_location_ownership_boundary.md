# DEC-022: 语义位置归属与 p0_map_manager 边界

## 状态

确认

## 背景

DEC-009 原文件存在但为空，已处理为异常占位 / 非有效事实源，不再作为 semantic location、AP Manager、语义位置归属或语义位置查询边界相关问题的有效 DEC 事实源。

DEC-005 已确认迭代一语义导航采用 YAML 语义位置表 + 规则匹配。

本决策确认迭代一基线下语义位置归属与 p0_map_manager / p0_semantic_nav 的职责边界。

本决策不表示相关实现已经完成，也不冻结接口字段、服务命名或命名空间为 V1.0 最终状态。

## 与既有 DEC 的关系

1. 本决策不推翻 DEC-005。
2. DEC-005 中“YAML 语义位置表 + 规则匹配”仍是迭代一语义导航基线。
3. 本决策只确认语义位置数据、语义标签到空间位姿 / 区域映射、语义位置查询能力的归属边界。
4. 本决策不定义开放集语义理解、LLM、完整语义地图研究路线、任务编排策略或导航执行算法。
5. 本决策不表示开放集、LLM、语义地图或未来研究增强已经完成，也不构成当前阶段义务。

## 决策

1. 在迭代一基线中，语义位置表、语义位置数据，以及语义标签到空间位姿 / 区域的映射能力，归属 p0_map_manager 管理。
2. p0_map_manager 对外提供语义位置查询能力。
3. p0_semantic_nav 在迭代一基线中通过查询接口向 p0_map_manager 获取语义位置对应的位姿或区域信息。
4. p0_semantic_nav 负责将语义目标和查询结果转换为导航目标，或将转换结果交由 p0_task_manager 组织执行。
5. 本决策不表示 p0_semantic_nav 永久只能通过当前查询接口工作。
6. 后续如需改变语义位置归属或查询机制，必须另行通过 CR / DEC、影响范围评估和回滚边界确认。

## 接口边界说明

1. 迭代一基线可采用语义位置查询接口连接 p0_semantic_nav 与 p0_map_manager。
2. 当前接口文档中的 QuerySemanticPose / /p0/map/query_semantic_pose 可作为 P1 骨架口径依据。
3. 本决策不冻结接口名称、字段结构或命名空间为 V1.0 最终状态。
4. 接口字段、命名空间和最终服务定义仍可在后续联调中按接口治理流程调整。

## 非目标范围

本决策不处理：

1. 不重新定义 DEC-005 的语义导航主路线。
2. 不引入 LLM 或开放集语义理解作为当前已完成能力。
3. 不定义完整语义地图研究路线。
4. 不定义任务编排策略。
5. 不修改导航执行算法。
6. 不修改源码、配置、launch、Docker 或部署文件。

## 风险

1. 如果将本决策误读为实现完成，可能造成下游规划或实现错误承接。
2. 如果将接口骨架误读为 V1.0 最终冻结，可能限制 P2-P5 联调调整。
3. 如果未明确与 DEC-005 的关系，可能被误解为推翻 YAML + 规则匹配基线。
4. 如果后续改变语义位置归属或查询机制未通过 CR / DEC，可能造成事实源漂移。

## 当前结论

本文件为确认 DEC。

本决策确认迭代一基线下语义位置表、语义位置数据、语义标签到空间位姿 / 区域映射能力，以及语义位置查询能力归属 p0_map_manager 管理；p0_semantic_nav 通过查询接口获取语义位置对应的位姿或区域，并负责将语义目标和查询结果转换为导航目标，或将转换结果交由 p0_task_manager 组织执行。

本决策不表示相关实现已经完成，不冻结接口字段、服务命名或命名空间为 V1.0 最终状态，也不推翻 DEC-005 的 YAML 语义位置表 + 规则匹配迭代一基线。
