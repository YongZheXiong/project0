# DEC-022: 语义位置归属与 p0_map_manager 边界

## 状态

草案 / 待确认

## 背景

DEC-009 原文件存在但为空，已被标记为异常占位 / 非有效事实源。

为避免继续使用空 DEC 承接 semantic location / AP Manager / 语义位置归属相关问题，本草案用于记录新的候选决策方向。

本草案在人工确认前不得作为有效 DEC 技术事实源。

## 与既有 DEC 的关系

1. 本草案不推翻 DEC-005。
2. DEC-005 中“YAML 语义位置表 + 规则匹配”仍是迭代一语义导航基线。
3. 本草案只讨论语义位置数据、语义标签到空间位姿 / 区域映射、语义位置查询能力的归属边界。
4. 本草案不定义开放集语义理解、LLM、语义地图研究路线、任务编排策略或导航执行算法。
5. 本草案不表示相关实现已经完成。

## 候选决策方向（待确认）

待人工确认的问题包括：

1. 语义位置表或语义位置数据是否由 p0_map_manager 归属管理。
2. p0_semantic_nav 是否通过查询接口获取语义位置对应的位姿或区域信息。
3. p0_map_manager 与 p0_semantic_nav 的边界是否仅限于位置查询与导航目标转换前后的职责划分。
4. 是否需要为语义位置查询定义单独接口或沿用已有接口设计。
5. 是否需要保留 YAML 表作为可编辑、可调试、可回退的语义位置来源。

## 非目标范围

本草案不处理：

1. 不重新定义 DEC-005 的语义导航主路线。
2. 不引入 LLM 或开放集语义理解作为当前已完成能力。
3. 不定义完整语义地图研究路线。
4. 不定义任务编排策略。
5. 不修改导航执行算法。
6. 不修改 Architecture 或接口文档。
7. 不修改源码、配置、launch、Docker 或部署文件。

## 风险

1. 如果过早确认语义位置归属，可能限制后续语义导航 / 地图管理设计。
2. 如果将草案误读为有效 DEC，可能造成下游规划或实现错误承接。
3. 如果未明确与 DEC-005 的关系，可能被误解为推翻 YAML + 规则匹配基线。
4. 如果继续使用 DEC-009 空文件，可能造成事实源误读。

## 当前结论

本文件当前仅为草案 / 待确认。

在人工确认前，本文件不得作为有效 DEC 技术事实源使用。
