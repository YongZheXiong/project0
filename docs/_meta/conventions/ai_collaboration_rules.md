# AI 协作规则

## 1. 文件作用

本文档用于规定 Project0 中 AI、Codex / Agent、人工决策和 Git 的长期协作边界。

它服务于单人 solo 开发、对话式 AI 辅助分析、Codex / Agent 受控执行、人工最终确认和 Git 留痕回滚的协作方式。本文档不定义项目技术事实，不替代 DEC、CR、README、DOC_INDEX、架构文档或 `AGENTS.md`。

`AGENTS.md` 是 Agent 进入仓库前的入口规则文件；本文档是长期协作规则细则。具体操作流程以 `docs/_meta/conventions/ai_workflow.md` 为准。

## 2. 角色分工

### 2.1 对话式 AI

对话式 AI 主要用于不直接进入仓库的思考和整理，包括：

1. 路线讨论。
2. 方案分析。
3. 复杂判断。
4. 提示词设计。
5. 复盘总结。

对话式 AI 可以帮助形成思路，但不能直接替代 DEC 结论、CR 范围、人工批准或 Git 提交。

### 2.2 Codex / Agent

Codex / Agent 主要用于仓库内的文件级工作，包括：

1. 仓库读取。
2. 只读审计。
3. 受控修改。
4. diff 检查。
5. 文件级执行。

Codex / Agent 必须先理解当前阶段、允许范围和禁止范围，再执行修改。涉及跨文件变更时，必须遵循 Plan -> Execute -> Verify -> Commit。

### 2.3 人工

人工负责最终控制权，包括：

1. 最终决策。
2. 批准修改范围。
3. 审查 diff。
4. 决定是否提交。
5. 确认是否进入下一阶段或扩大范围。

AI 可以提出建议、列风险、执行批准范围内的修改，但不能代替人工确认关键边界。

### 2.4 Git

Git 负责工程状态管理，包括：

1. 隔离分支。
2. 提交记录。
3. 回滚。
4. 合并。

Git 历史应反映真实变更，不用提交记录掩盖未审查、越界或事实不一致的修改。

## 3. 人工确认原则

以下事项必须经人工确认：

1. 修改已确认 DEC 的状态、结论或替代关系。
2. 修改 Architecture、Planning、Definition 中的事实边界。
3. 修改接口、硬件事实、BOM、采购清单或部署边界。
4. 进行跨文件修改。
5. 扩大阶段范围或引入新阶段任务。
6. 执行 `git add`、`git commit`、`git reset`、`git checkout`、`git stash apply` 或 `git stash pop`。

人工确认应明确允许修改文件、禁止修改文件、验证要求和是否允许提交。

## 4. CR / DEC 约束

CR 用于管理一次变更的原因、范围、风险、验证和结果。

DEC 用于记录已经确认的重要技术决策、路线选择和决策理由。

协作规则如下：

1. 跨文件修改必须先建立或引用 CR。
2. Agent 只能修改人工批准或 CR 明确允许的文件。
3. CR 不替代 DEC。
4. CR 不能绕过人工确认去修改已确认 DEC。
5. DEC 是技术决策事实源，不能由 Agent 自动推翻。
6. 废弃 DEC 时应保留历史可追溯性，不直接抹除决策背景。

## 5. 安全与边界

安全底线优先于性能、进度和功能扩展。

Codex / Agent 不得削弱以下边界：

1. 安全机制。
2. 人工接管。
3. 急停。
4. 系统模式仲裁。
5. 电源边界。
6. 风险区域约束。
7. 已确认的硬件、通信和架构边界。

涉及安全、急停、人工接管、电源或电机边界的修改，必须先进行影响分析，并经人工确认后再执行。

## 6. Agent 使用红线

Codex / Agent 不得执行以下行为：

1. 未经批准直接修改文件。
2. 自动重写整个 `docs/`。
3. 自动修改已确认 DEC 结论。
4. 自动创建未来目录。
5. 自动推进 P2-P6 或 P7-P10。
6. 在不看 diff 的情况下提交。
7. 将迭代二增强内容提前写成迭代一必须实现项。
8. 将项目0扩展为机械臂、复杂抓取、多机器人、无人机、人形机器人或纯仿真项目。
9. 在未完成 P1.3 BOM / 采购清单人工确认前直接采购，或写成采购已完成。

如果任务需要突破既定范围，Agent 应先停止执行，说明原因、影响和建议处理方式。

## 7. Git 权限边界

Git 使用规则如下：

1. `main` 是稳定主线。
2. `governance` 是治理分支。
3. 一个主题尽量一个 commit。
4. commit message 使用 `type(scope): description`。
5. 未 push 前可 amend。
6. 合并 `main` 前必须最终验证。
7. 不满意时优先用 `git restore` / `git revert`，不在坏状态上继续手改。

Agent 不应自行执行 `git add`、`git commit`、`git reset`、`git checkout`、`git stash apply` 或 `git stash pop`，除非人工明确授权。
