# OpenCTR H60 部署入口

> 文档状态：正式入口 / 运动锁定固件无电机 bring-up 已完成 / 动力部署未放行
> 适用版本：OpenCTR H60 V3.7 / STM32F407VET6
> 依据：DEC-047、DEC-046、CR-117、CR-111

## 当前已确认

1. H60 作为四路 MC520P56 电机/编码器的底层控制器。
2. 目标通信为 Orin NX UART；永久接线前必须关闭 H60 掉电反供电风险。
3. 板载 VIN ADC `PC0` 承接主电池电压监测；外置 Keyes 模块不装。
4. H60 J2/J3 不为 Orin 或 Mid360 供电。
5. H60 板载开关保持 ON；外置主开关管理整车电源。当前没有独立急停或继电器，主开关不得称为急停。
6. Project0 自有 `v0.1.1-safe-bringup` 已在 MA-MD 全空条件下完成刷写、官方验证、独立完整回读和冷启动通信检查；固件仍编译期锁死运动输出。

VIN ADC 只在 H60 上电时可用。H60 支路故障、维护断电或整车断电后，Orin 不再获得该电压遥测；它用于上电期间的母线电压观测，功能范围不含持续 SOC 监测。当前没有车载电流采样。

## 部署顺序与当前进度

1. H0：已完成部分实物与不上电核对，但完整到货、针序、资料和阶段记录尚未关闭，H0 仍为 `NOT RUN`。
2. 已建立不依赖不明 EXE/预编译 HEX 的可复现固件构建路径，并记录工具版本、命令、产物散列和厂家完整 Flash 回滚件。
3. 已在不接电机条件下完成 `v0.1.1` 冷启动、VIN 原始采样、串口遥测、STOP 和 ARM 运动锁检查；这不是限流电源、低压轨或 VIN 多点校准验收。
4. `firmware/h60_motion_control_firmware_requirements_v0_2.md` 已部分实现；PWM、闭环速度、斜坡、反转死区、完整故障注入和标定仍待后续门。
5. 完成 UART 反供电保护后，再进行 Orin 双向通信和故障注入。
6. 按 H0-H8 计划逐级进入电机、动力和落地测试。

H60 V3.7、四组 MC520 和九根线的到货身份/线序已由恢复的历史原图、用户现场清单、逐线测量和原厂资料关闭，`H0 = PASS`；Project0 `v0.1.1` 也已完成无电机安全 bring-up。H1/H3-H8 仍未通过，H2 仅为当前最小三支路 PARTIAL；Orin 侧仍是旧 STM32 文本桥，UART 单侧掉电反供电、带载输出、编码器方向/CPR、PWM/闭环、温升、回生、停车距离和完整故障注入均未关闭。厂商示例、无电机 bring-up 和空载万用表 `0 V` 观察都不能自动关闭这些门，也不放行接电机或运动。

公开产品入口：https://www.xtark.cn/product/show.php?itemid=7 。H0 已以到货 V3.7 实物丝印、4×MC520 铭牌、九根线直通记录和随附资料关闭；后续电气与运动功能仍按 H2-H7 真实测量为准。
