## 2. 当前硬件边界

当前 H60 新车不安装独立急停按钮、继电器、急停 GPIO、Keyes 或 ACS712。车载采样只有 H60 `PC0` VIN ADC 电压；电流仅能由外部仪表在台架中临时测量。主开关用于整车断电，不得记作急停验收。

没有独立急停意味着 H8 必须额外满足：空旷平坦区域、远离楼梯口/天井边缘/电梯口/排水槽、最低速度与加速度、短距离、操作者与主开关直接可达、必要的非导电机械后备约束，以及用户当次明确授权。

## 3. H0–H2：不上电阶段

1. H0 逐件拍摄标签、接口和损伤，核对 H60 版本、MC520 数量/型号/减速比/编码器线序和所有拟复用件状态。
2. H1 对 28 个 STEP 对应实物进行孔位、板厚、平面度、打印尺寸、连接器、散热、线束和拆卸路径试装；实物通过状态以该轮检查结果为准。
3. H2 在电池拆除条件下核对完整电源树。不得残留旧急停线圈、继电器、ACS712 或旧平台路号。
4. 记录每条支路的线径、端子、保险候选与选择依据；不凭经验直接增大保险。

## 4. H3–H4：低能量供电与通信

1. 首次 H60 上电不接电机，优先使用限流电源；分别记录启动电流、输入电压、低压轨和温升。
2. Orin 与 Mid360 分支独立验证，确认 DC-DC 极性、12 V 输出、冷启动和短时稳定性。
3. 分别制造 H60 断电/Orin 上电和 Orin 断电/H60 上电，测量对侧电源轨、UART 电平和反灌电流。
4. 验证 H60/Orin 任一侧重启、UART 断开和恢复后均保持 `DISARMED`，旧会话、旧序号和缓存命令无效。
5. 永久运动线束和 H5/H6 的进入条件是 H4 通过。

## 5. H5：固件故障注入

依据 `firmware/h60_motion_control_firmware_requirements_v0_2.md`，至少覆盖：上电/复位零 PWM、ARM 条件、输入回中、STOP/DISARM、命令超时、心跳丢失、CRC 错误、过长帧、序号回退、Orin 重启、IWDG 和异常入口。每次失败都写入 P2 日志，修复必须指向真实源码与回归结果。

## 6. H6–H7：架空运动

1. 车辆可靠架空，轮周净空，先单通道后四通道，使用最低有效 PWM/速度与短脉冲。
2. 四路分别确定 Motor ±、A/B、计数符号、计数边沿和 CPR，禁止迁移旧 JGB 数据。
3. 验证正反转、左右转、停止、斜坡、反转零输出、通信断联停车和人工接管。
4. 使用外部仪表测量单路到四路的电流、压降与温升；这些数据属于台架测量，车辆当前没有电流采样通道。
5. 用合适的探头记录刹车、反转和主开关断开时的 H60 VIN 波形。无可信波形、温升或停车证据则 H7 不通过。
6. 完成 VIN ADC 多点校准并记录误差。

## 7. H8：落地低速

H8 必须由用户在当次现场状态下明确授权。前置条件包括 H0–H7 全部通过、结构与线束固定、场地隔离、人员和障碍清空、主开关可直接触达、操作者持续目视、初始速度不高于 `0.1–0.2 m/s` 且加速度保守。

按短距离前进、停车、后退、转向、通信断联停车、人工接管的顺序逐项执行。任何异常立即停止命令并关闭主开关，回到断电检查；不得靠近高风险区域，不得无人测试。

## 8. 记录与完成条件

- 每门记录硬件/软件版本、日期、条件、命令、原始结果、失败、修复和证据路径；
- 结果应记录硬件/固件版本、条件、原始数据与证据文件；
- P2 只有在 H0–H8、真实代码、通信、里程计、接管和文档记录全部通过后才完成，并在用户批准后发布 v1.1；
- 旧平台 Stage D/E、CPR、轮径、动力和急停记录不自动关闭本计划任何门。
