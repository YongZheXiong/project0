## 2. 架构目标与原则

项目0面向室内走廊真实场景，以真机闭环为验收标准。计算与通信架构必须服务于这一定位，并与系统总架构保持一致。

### 2.1 单主计算平台

系统只有一个明确的主计算中心：**Orin NX**。

### 2.2 单底层执行控制平台

系统只有一个明确的底层执行控制中心：**OpenCTR H60 V3.7**。

### 2.3 上层集中、下层确定

- Orin NX 负责上层系统闭环（感知、定位、导航、任务、运行监测与仲裁、系统管理、数据记录）
- H60 负责底层实时闭环（电机控制、编码器读取、本地超时、看门狗和故障撤 PWM）

这是整份文档最核心的职责划分原则。后续所有通信链路和节点落位均以此为基础。

### 2.4 先支撑迭代一，再承接迭代二

计算与通信架构必须先支撑迭代一单车闭环，再在不推翻主从骨架的前提下承接迭代二增强。

### 2.5 外部操作终端不纳入正式计算节点

当前没有独立急停按钮。人工接管输入采用飞智黑武士2手柄，通过 2.4G USB 接收器接入 Orin NX，并由 Orin NX 上的 teleop / 手动控制节点生成运动意图，经运行仲裁后下发到底盘链路。

## 3. 计算实体划分

项目0采用"单主计算平台 + 单底层控制平台 + 外设接入"的结构。

### 3.1 Orin NX

系统唯一主计算与主控平台。

承担：

- 感知接入与管理（Mid360、D435、IMU 数据接收与发布）
- 定位、建图、地图管理
- 导航与避障
- 语义导航与任务调度
- 安全监测与上层安全处置
- 系统管理、自检、运行监控
- 数据记录与调试支撑

### 3.2 H60

系统唯一底层执行控制平台。

承担：

- 电机驱动与 PID 速度闭环控制
- 编码器读取与里程计初步计算
- 底盘安全保护（速度限幅、通信超时停车、IWDG 和异常撤 PWM）
- 接收 Orin NX 下发的速度指令
- 向 Orin NX 上传编码器数据与底层状态

### 3.3 外设接入

以下设备直接接入 Orin NX：

| 设备 | 接入方式 | 角色 |
|------|---------|------|
| Livox Mid360 | USB/以太网 | 3D激光雷达，提供点云与内置IMU数据 |
| Intel RealSense D435 | USB | 深度相机，提供RGB与深度图像 |

> **D435 在迭代一中的角色说明**：D435 在迭代一中仅作为深度/视觉数据源接入系统，用于辅助感知、数据记录（rosbag2 录制）和调试可视化（RViz2 观测）。**D435 数据在迭代一中不流向 SLAM 节点组，不参与 FAST-LIO2 的定位融合**。迭代二前段才将 D435 视觉/深度信息融入定位系统。

以下设备接入 H60：

| 设备 | 接入方式 | 角色 |
|------|---------|------|
| MC520P56 四路编码器 | H60 四路 AB 编码器接口 | 提供四轮原始计数与速度反馈 |
| MC520P56 四路电机 | H60 集成 AT8236 电驱 | 接收本地闭环输出；每路限流与热能力待验 |

### 3.4 IMU 数据来源说明

迭代一中 IMU 数据的主路径为：**Mid360 内置 IMU，通过 Livox ROS2 驱动在 Orin NX 上直接发布** 。

备选外置 IMU 不纳入当前 H60 重建前置；如后续需要，另立 CR/DEC 评估接入和时间同步。

## 4. 通信链路定义

### 4.1 Orin NX ↔ H60 主从链路

| 项目 | 说明 |
|------|------|
| 物理链路 | 受掉电反供电保护的 UART；永久接线在 H4 通过后冻结 |
| 协议 | 版本 + 长度 + 会话/序号 + 数据 + CRC + 状态/故障帧 |
| 下行数据（Orin NX → H60） | ARM/DISARM/STOP、目标线速度、目标角速度、心跳 |
| 上行数据（H60 → Orin NX） | 四轮编码器/轮速、VIN、状态机、故障和固件版本 |
| 通信频率 | 建议 50-100Hz |
| 异常处理 | H60 本地短超时撤 PWM；非法/过期/CRC 错帧失效导向；IWDG 与异常入口先停车 |

### 4.2 感知接入链路

| 传感器 | 物理接口 | 接入平台 | ROS2 驱动 | 数据流向 |
|--------|---------|---------|-----------|---------|
| Mid360 | USB/以太网 | Orin NX | livox_ros_driver2 | → SLAM节点组、导航节点组、数据记录节点组 |
| D435 | USB | Orin NX | Intel RealSense ROS2 Wrapper | → 数据记录节点组、调试可视化（迭代一）；迭代二增加→SLAM节点组 |
| IMU（主路径） | Mid360内置 | Orin NX（Livox驱动发布） | livox_ros_driver2 | → SLAM节点组 |

### 4.3 停止、失能与人工接管通信路径

STOP/DISARM、底层超时停车和人工接管在通信层面的落位必须明确：

| 能力 | 通信路径 | 说明 |
|----------|---------|------|
| **手柄人工接管** | 飞智黑武士2手柄 → 2.4G USB 接收器 → Orin NX → 手动控制节点 → 运行仲裁 → 底盘桥接 → 受保护 UART → H60 | 人工输入经版本化协议和显式 ARM 会话下发；不采用航模接收机直连底层控制器 |
| **STOP / DISARM** | Orin NX 运行仲裁 → 底盘桥接 → 受保护 UART → H60 | 检测到异常或人工请求后发送 STOP/DISARM；H60 仍以本地超时、IWDG 和故障撤 PWM 兜底 |
| **人工断电** | 操作者 → 外置主开关 → 整车电源 | 当前无独立硬件急停；主开关只作人工断电处置，不经过通信且不称急停 |

### 4.4 数据记录链路

rosbag2 和 ROS2 标准日志统一运行在 Orin NX 上。录制范围覆盖：

- 传感器原始数据话题（Mid360 点云、D435 RGB/深度、IMU）
- 里程计与定位结果话题
- 导航路径与速度话题
- 任务状态话题
- 停止、失能、故障、接管事件与系统状态话题

数据记录与长期归档采用分层链路：

1. 现场 rosbag、日志和临时地图先写入 Orin NX 内置 512GB NVMe；
2. 停止录制后检查数据有效性，再执行筛选、裁剪或压缩；
3. 通过 USB 将关键数据复制到 2TB 便携式机械硬盘；
4. 完成回放抽检和 SHA-256 校验后，才能清理 Orin 上的临时数据；
5. U 盘只用于换机和日常小文件周转，不承担 Project0 原始数据长期归档。

外置机械硬盘不进入实时数据通路，也不作为运动中 rosbag 主录制盘。归档复制属于测试结束后的维护操作，不得影响控制、运行仲裁、感知或导航主链路。

### 4.5 通信链路总览图（文字描述）

```
外部操作者
  ├─ 外置主开关 ──→ [人工整车断电；不称急停]
  └─ 飞智黑武士2手柄 ──→ 2.4G USB 接收器 ──→ Orin NX（teleop / 手动控制节点）

Orin NX（主计算平台）
  ├─ USB/以太网 ←── Mid360（点云 + IMU）
  ├─ USB ←── D435（RGB + 深度）
  ├─ ROS2: teleop / 手动控制节点 ──→ cmd_vel ──→ 底盘桥接节点
  ├─ 受保护 UART ←→ H60（ARM/STOP/速度指令↓ / 编码器+VIN+状态+故障↑）
  ├─ ROS2 内部通信（节点组之间）
  └─ 内置 NVMe 录制 ──→ 筛选 / 压缩 ──USB──→ 外置机械硬盘归档

H60（底层控制平台）
  ├─ 四路定时器 ←── MC520 AB 编码器
  ├─ 四路 PWM ──→ 板载 AT8236 ──→ MC520 电机
  └─ UART ←→ Orin NX
```

## 5. 系统总架构在计算平台上的落位

### 5.1 主链路落位

系统总架构定义的五层主链路在计算平台上的落位关系：

| 主链路层级 | 计算平台 | 说明 |
|-----------|---------|------|
| 执行层 | H60 | 四路电机控制、编码器读取、本地超时、看门狗和故障撤 PWM 在 H60 实时闭环中完成 |
| 感知层 | Orin NX | 传感器驱动与数据发布统一在 Orin NX 上 |
| 空间认知层 | Orin NX | FAST-LIO2 建图/定位运行在 Orin NX 上 |
| 行动规划层 | Orin NX | Nav2 导航框架运行在 Orin NX 上 |
| 任务决策层 | Orin NX | BehaviorTree.CPP + 语义导航逻辑运行在 Orin NX 上 |

### 5.2 辅助链路落位

| 辅助链路 | 计算平台 | 说明 |
|----------|---------|------|
| 运行约束链路 | H60（限幅、超时、IWDG、故障撤 PWM）+ Orin NX（监测、STOP/DISARM、接管仲裁）+ 主开关人工断电 | 当前无独立急停/继电器；不作产品安全能力声明 |
| 系统管理链路 | Orin NX | 启停管理、状态管理、自检、配置管理、运行监控统一在 Orin NX |
| 数据记录链路 | Orin NX | rosbag2 录制和日志输出统一在 Orin NX |

## 6. ROS2 节点组粗粒度规划

以下为 Orin NX 上运行的 ROS2 节点组规划。**本节只定义节点组及其系统角色，不定义组内各节点的具体拆分和职责——组内节点拆分由软件架构文档承接** 。

| 节点组 | 运行平台 | 系统角色 | 对应总架构模块 |
|--------|---------|---------|---------------|
| 感知接入节点组 | Orin NX | 运行传感器驱动，发布点云、图像、深度、IMU 等感知数据 | 感知模块 |
| SLAM 节点组 | Orin NX | 运行 FAST-LIO2，完成建图与定位 | 空间认知模块 |
| 导航节点组 | Orin NX | 运行 Nav2 框架，完成全局路径规划、局部避障、路径跟踪与代价地图管理 | 行动规划模块 |
| 任务决策节点组 | Orin NX | 运行 BehaviorTree.CPP 与语义导航逻辑，完成任务管理与语义目标转换 | 任务决策模块 |
| 底盘桥接节点组 | Orin NX | 负责 Orin NX 侧的 UART 通信处理，将 ROS2 速度指令转为串口数据下发，将串口上传数据转为 ROS2 话题发布 | 执行模块（Orin NX 侧桥接） |
| 运行仲裁节点组 | Orin NX | 监控定位/感知/导航/通信/电压等状态，检测异常，发布 STOP/DISARM 并仲裁手动/自动运动意图 | 运行约束模块 |
| 系统管理节点组 | Orin NX | 管理系统模式、状态、自检、启动流程、参数配置与运行监控 | 系统管理模块 |
| 数据记录节点组 | Orin NX | 运行 rosbag2 录制与日志管理 | 数据记录与复盘模块 |

> H60 上不运行 ROS2 节点，运行运动控制固件，负责四路电机控制、编码器读取、本地状态机、超时/IWDG/故障撤 PWM 和 UART 通信。仓库现有 STM32 源码只作迁移骨架与历史证据。

## 7. 数据流、控制流与状态流大方向

### 7.1 数据流

```
Mid360 ──点云+IMU──→ 感知接入节点组 ──→ SLAM节点组 ──→ 导航节点组
D435 ──RGB+深度──→ 感知接入节点组 ──→ 数据记录节点组（迭代一）
H60 ──编码器+VIN+状态+故障──→ 底盘桥接节点组 ──→ SLAM节点组 / 导航节点组 / 安全节点组
```

### 7.2 控制流

```
任务决策节点组 ──导航目标──→ 导航节点组 ──速度指令──→ 安全仲裁──→ 底盘桥接节点组 ──受保护 UART──→ H60 ──PWM──→ 电机
```

### 7.3 状态流

```
各节点组 ──运行状态──→ 系统管理节点组（汇总系统状态）
各节点组 ──异常状态──→ 运行仲裁节点组（检测异常、触发 STOP/DISARM）
各节点组 ──话题数据──→ 数据记录节点组（全程录制）
```

## 8. 迭代视角下的计算与通信架构稳定性

### 8.1 迭代一中的作用

在迭代一阶段，本架构支撑固定场景最小闭环：

- Orin NX 运行感知、SLAM、导航、任务、运行仲裁、管理和记录逻辑
- H60 运行四路电机控制、编码器读取、本地超时、看门狗和故障撤 PWM
- UART 连接上下位机
- Mid360 提供点云与 IMU 数据用于 FAST-LIO2
- D435 接入但仅用于记录和调试，不参与定位融合
- 飞智黑武士2手柄通过 2.4G USB 接收器接入 Orin NX，由 teleop / 手动控制节点生成运动意图，经运行仲裁与底盘桥接下发到 H60

### 8.2 迭代二中的变化

迭代二在不改变主从骨架的前提下承接增强：

- **迭代二主线**（优先推进）：D435 数据流从"仅记录"扩展为"流向 SLAM / 定位相关节点组参与视觉或深度辅助融合"；编码器里程计从"独立发布"扩展为"融入定位系统"；这些变化均在 Orin NX 内部的 ROS2 节点组之间发生，不改变 Orin NX ↔ H60 的通信结构
- **迭代二后续增强**（在融合主线基本完成后推进）：可能新增外挂回环检测、地图一致性修正与退化处理逻辑；IEKF / FAST-LIO 核心研究仅作为有余力时的候选深化项，同样不改变计算与通信骨架

**结论：迭代二所有增强均为 Orin NX 内部节点组的能力增强或数据流扩展，主从架构骨架不变，通信链路不变。**

## 10. 总结

项目0计算与通信架构可以概括为：

> 项目0采用 Orin NX 主计算机与 OpenCTR H60 V3.7 底层执行控制器的主从架构。感知、导航、任务、人工/自动仲裁、系统管理与记录位于 Orin NX；四路电机/编码器闭环、本地限幅、超时、看门狗与故障撤 PWM 位于 H60。Mid360 和 D435 接入 Orin NX；运动指令通过受保护、单侧掉电不反灌的 UART，以版本化协议和显式 ARM 会话下发 H60。当前无独立急停/继电器或反馈 GPIO；任一侧重启或通信恢复都不得自动恢复运动。
