# H60 运动控制固件要求 v0.2

> 状态：正式需求 / 尚未实现
> 依据：当前 H60 + MC520 数字基线与公开验收门
> 目标：定义 H60 获得动力测试准入前的最小可验证固件行为

## 1. 状态机

最小状态为 `BOOT -> DISARMED -> ARMED -> FAULT`。

1. 上电、复位、棕断恢复和看门狗复位后必须进入 `DISARMED`，四路 PWM 为 0。
2. `DISARMED` 清除上一会话的速度目标、PID 状态、方向切换状态和命令序号。
3. 只有自检、通信心跳、故障状态和命令新鲜度通过，并收到新会话显式 ARM，才能进入 `ARMED`。
4. ARM 前速度目标必须为零，人工操纵输入必须回中；保持的摇杆或缓存 `cmd_vel` 不得通过。
5. STOP、DISARM、通信超时、非法帧、序号回退、看门狗前置、异常入口和本地故障必须先撤销四路 PWM，再清控制状态。
6. H60 或 Orin 重启、UART 断开与恢复都不得自动恢复 `ARMED`。

## 2. 通信协议

协议至少包含：

- 固定帧头、协议版本、显式长度和最大长度；
- 会话 ID、单调序号和 CRC；
- ARM、DISARM、STOP 和速度命令；
- 心跳与短命令超时；
- 四轮原始计数、速度、故障、VIN、固件版本和状态机状态；
- 对越界长度、未知命令、重复/过期序号和 CRC 错误的失效导向处理。

控制命令超时可从 `200–300 ms` 台架起步，最终值必须结合 ROS2 调度、UART 周期和停车实测冻结。记录选择时要列出候选值、风险和测试结果。

## 3. 电机控制

1. 四路 MC520P56 独立采集 AB 编码器，计数边沿、CPR、减速比和 A/B 方向必须可配置并实测标定。
2. 速度闭环应包含输出限幅、加减速斜坡、积分抗饱和和反转零输出保持。
3. 禁止从正向 PWM 直接跳到反向 PWM；必须先减到零并满足最小死区。
4. 当前没有电流采样，也没有基于电流遥测的软件堵转保护；堵转风险由驱动限制、保守命令和受监督台架测试约束。
5. H60 `PC0` VIN ADC 必须多点校准，并上报原始值、换算值和校准版本；电压采样不替代 BMS 或保险。

## 4. 异常与看门狗

1. 启用 IWDG；所有异常处理入口必须先将电机 PWM 置零。
2. HardFault、MemManage、BusFault、UsageFault、断言失败和不可恢复协议错误不得在保留旧 PWM 的死循环中停留。
3. 在不延迟撤 PWM 的前提下记录故障与复位原因。
4. UART 和缓冲区访问先检查长度与索引，不信任上位机输入。
5. 默认参数、校准缺失、版本不兼容或关键自检失败时保持 `DISARMED`。

## 5. 验收门

- 可复现构建，固件版本、工具链与散列可记录；
- 上电和复位重复测试不出现非零 PWM；
- UART 断开、停止发送、乱码、CRC 错、过长帧和 Orin 重启均自动停车；
- 看门狗与故障注入先撤 PWM；
- 四轮架空方向、超时、斜坡和反转通过；
- VIN ADC 多点校准误差有记录；
- 只有电源、反供电、温升、结构和前置测试门同时通过，且用户明确授权，才进入落地低速测试。

## 6. 记录要求

每次参数或方案选择都应随实现记录选择理由、真实源码、构建输出、测试结果和证据路径。失败和未完成项同样记录。
